# ADR-0010: Despliegue gratuito — Vercel + Render + Supabase

## Estado
Aceptado. **Evidencia pendiente:** despliegue real y URL pública.

## Criterios de evaluación
- Gratuito.
- Pocos pasos y despliegue automatizable desde GitHub Actions (CD).
- URL pública HTTPS para que el docente use el sistema.
- Soporte de contenedores Docker y variables de entorno (Factores III, V, VII).

## Candidatos
- **Vercel (front) + Render (back, Docker) + Supabase (BD y archivos).**
- Railway (todo en uno, con crédito limitado).
- Azure / AWS.

## Análisis
| Candidato | Cumple | Razón |
|---|---|---|
| **Vercel + Render + Supabase** | Sí | Planes gratuitos; despliegue desde Git o por *hook* y CLI; HTTPS incluido. |
| Railway | Parcial | Más simple en un solo lugar, pero con crédito gratuito limitado. |
| Azure / AWS | Parcial | Más control y más configuración; riesgo de tiempo y costo. |

**Limitaciones del entorno gratuito (riesgos asumidos):**
| Limitación | Mitigación |
|---|---|
| Render suspende el servicio por inactividad y el primer arranque tarda decenas de segundos. | Despertar el servicio antes de la sustentación con una petición a `/actuator/health`; opcional, un monitor de *ping*. |
| Render gratuito bloquea SMTP (25/465/587). | Correo por API HTTPS (ADR-0006). |
| El proyecto gratuito de Supabase puede pausarse por inactividad. | Verificar y reactivar el mismo día. |
| Una sola instancia. | Arquitectura sin estado lista para escalar; limitación del entorno y no del diseño. |

## Recomendación
- **Frontend** en Vercel, **backend** en Render (imagen Docker), **BD y archivos** en Supabase.
- Configuración solo por **variables de entorno**.
- CD por GitHub Actions: *deploy hook* de Render y CLI de Vercel, con prueba de humo posterior.

## Consecuencias
- Documentar en el Manual de puesta a punto cada variable de entorno y el procedimiento de reactivación.
