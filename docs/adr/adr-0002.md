# ADR-0002: Stack — Java + Spring Boot y React PWA (Mobile First)

## Estado
Aceptado.

## Criterios de evaluación
- Dominio del autor para **sustentar y modificar código en vivo**.
- Madurez del ecosistema de pruebas, calidad y arquitectura (JUnit, Testcontainers, ArchUnit, Sonar).
- Cumplimiento de DRV-001 (90 % móvil): PWA, rendimiento, instalación.
- Tiempo de construcción y despliegue gratuito.

## Candidatos
- Backend: **Java + Spring Boot**, NestJS, FastAPI.
- Frontend: **React + Vite (PWA)**, Angular, Vue.

## Análisis
| Candidato | Cumple | Razón |
|---|---|---|
| **Spring Boot** | Sí | Dominio del autor; Spring Security, Actuator, Resilience4j, ArchUnit y Testcontainers integran directamente con los requisitos. |
| NestJS / FastAPI | Parcial | Viables, pero con menor dominio para la sustentación en vivo. |
| **React + Vite** | Sí | Construcción y arranque rápidos, ecosistema PWA y de pruebas (Vitest, Playwright), despliegue inmediato en Vercel. |
| Angular | Parcial | Más estructura y ceremonia con poco tiempo. |
| Vue | Sí | Viable; se prefiere React por el ecosistema de PWA y pruebas. |

## Recomendación
- Backend: **Java 25 (LTS) + Spring Boot 4.1.1 + Maven**. Las versiones exactas se fijan en `pom.xml` y están registradas en el diagrama de componentes (ver documento 12 §4 para el estado de verificación de cada una).
- Frontend: **React + Vite como PWA**, diseño responsivo desde 360 px, rutas con carga diferida, *service worker* con *stale-while-revalidate*.

## Por qué Spring Boot 4 y no 3.5
Spring Boot 3.5 terminó su soporte de código abierto el 30-jun-2026, así que un proyecto nuevo en noviembre de 2026 debe arrancar sobre la línea 4.x. Spring Boot 4 trae cambios que afectan el código y se tuvieron en cuenta en el diseño: starters modulares con nuevos nombres (`spring-boot-starter-webmvc`, `spring-boot-starter-flyway`, `spring-boot-starter-security-oauth2-resource-server`), Jackson 3 por defecto y Spring Framework 7.

## Decisiones derivadas de la versión
- **JWT con Nimbus JOSE** (incluido en `spring-boot-starter-security-oauth2-resource-server`), firmado con HS256 y secreto por variable de entorno. Se descarta `jjwt` para evitar una librería con versión propia y su dependencia de Jackson 2.
- **Clientes HTTP con `RestClient`** (incluido en Spring Framework) para Brevo, Twilio y Supabase Storage, sin SDK de proveedor: menos dependencias, y cada adaptador sigue siendo una clase pequeña que implementa su puerto.
- **Resilience4j 2.4.0** con el artefacto `resilience4j-spring-boot4` (no está incluido en el BOM de Resilience4j; se declara su versión).

## Consecuencias
- Frontend y backend son **dos repositorios** independientes (Factor I).
- El contrato entre ambos es la API REST documentada con OpenAPI.
