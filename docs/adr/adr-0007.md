# ADR-0007: Seguridad — Spring Security, JWT y RBAC

## Estado
Aceptado.

## Criterios de evaluación
- Seguridad demostrable (DRV-005) y control del modelo de roles jerárquico.
- Tiempo de implementación y dominio del autor.
- Escalabilidad sin sesión compartida (Factor VI).
- Costo.

## Candidatos
- **Spring Security + JWT propio + BCrypt.**
- Firebase Authentication.
- Auth0 / Keycloak.

## Análisis
| Candidato | Cumple | Razón |
|---|---|---|
| **Spring Security + JWT** | Sí | Integra el RBAC por rol institucional y las reglas de ámbito; sin dependencia externa; sin estado. |
| Firebase Auth | Parcial | Rápido, pero el modelo de roles jerárquicos y de aprobación quedaría repartido entre el proveedor y la BD. |
| Auth0 / Keycloak | Parcial | Robustos; Auth0 con costo y Keycloak con operación adicional, excesivos para la línea base. |

**FODA.** *Fortalezas:* control total y sin costo. *Debilidades:* la seguridad queda a cargo del equipo, por lo que se apoya en librerías estándar y pruebas. *Oportunidades:* SSO institucional con OIDC. *Amenazas:* mala configuración.

## Recomendación
- Claves con **BCrypt**; **JWT de vida corta** firmado con secreto de ≥ 256 bits desde variable de entorno.
- **Denegar por defecto**; `@PreAuthorize` en el borde y regla de negocio en el caso de uso.
- **Secretos** solo en variables de entorno y GitHub Secrets.
- Perímetro: CORS restringido, límite de tasa (Bucket4j), cabeceras seguras, errores `problem+json` sin trazas.
- **Límite técnico** de tamaño de petición (el "sin límite de longitud" del enunciado se interpreta como ausencia de límite de negocio; supuesto S-04).

## Consecuencias
- Se requieren pruebas automatizadas de autorización (EC-01, EC-02).
