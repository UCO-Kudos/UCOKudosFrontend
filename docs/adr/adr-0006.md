# ADR-0006: Notificaciones multicanal — Brevo, Twilio y SSE

## Estado
Aceptado, con limitaciones conocidas del entorno gratuito. **Evidencia pendiente:** envío real de los tres canales desde el despliegue.

## Criterios de evaluación
- Costo (debe ser gratuito para la demostración).
- Compatibilidad con el hospedaje gratuito.
- Rapidez de configuración.
- Facilidad de reemplazo (puerto por canal).

## Candidatos
- **Correo:** SMTP de Gmail, Resend, **Brevo (API HTTPS)**.
- **WhatsApp:** **Twilio Sandbox**, Meta WhatsApp Cloud API.
- **Push en tiempo real:** **SSE**, WebSocket, Firebase Cloud Messaging.

## Análisis
| Canal | Candidato | Cumple | Razón |
|---|---|---|---|
| Correo | SMTP Gmail | **No** | Render gratuito **bloquea** los puertos SMTP 25/465/587 (vigente desde septiembre de 2025). |
| Correo | Resend | Parcial | Sin dominio propio verificado solo envía al correo de la propia cuenta. |
| Correo | **Brevo API** | **Sí** | Funciona por HTTPS; plan gratuito de 300 correos/día; basta verificar el remitente. |
| WhatsApp | **Twilio Sandbox** | **Sí, con límites** | Alta en minutos; solo escribe a quien envió el código *join*; la sesión vence a los 3 días; mensajes libres solo dentro de 24 h desde el último mensaje del usuario; fuera, solo plantillas del sandbox. |
| WhatsApp | Meta Cloud API | Parcial | Más pasos de alta y las mismas restricciones de plantilla. |
| Push | **SSE** | **Sí** | Unidireccional, estándar, suficiente: solo se notifica "si está conectado". |
| Push | WebSocket | Parcial | Bidireccionalidad innecesaria. |
| Push | FCM | Parcial | Útil para Web Push con la app cerrada (evolución). |

## Recomendación
- **Correo:** `BrevoEmailSenderAdapter` por API HTTPS.
- **WhatsApp:** `TwilioWhatsAppSenderAdapter` con el sandbox.
- **Push:** `SsePushNotifierAdapter` con registro de conexiones en memoria, *heartbeat* periódico y autenticación por cabecera `Authorization` (cliente con `fetch`).
- Todos tras sus puertos, con **reintentos, *timeout* y *circuit breaker*** (Resilience4j) y registro de resultado en `notificacion` y `auditoria`.

## Consecuencias y limitaciones
- **WhatsApp:** cada destinatario de la demostración debe enviar el mensaje *join* previamente (y repetirlo si pasaron más de 3 días). Los destinatarios que no se unieron recibirán un error `63015`, que se audita como fallo. Evolución: remitente de WhatsApp Business registrado con plantillas aprobadas.
- **SSE:** el registro de conexiones es por instancia; con varias instancias se requiere Redis Pub/Sub.
- **Correo:** el remitente verificado puede ser tratado como correo no deseado por algunos proveedores; se revisa la carpeta de spam en la demostración.
