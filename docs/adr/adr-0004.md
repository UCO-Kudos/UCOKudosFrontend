# ADR-0004: Adjuntos en almacenamiento de objetos privado

## Estado
Aceptado.

## Criterios de evaluación
- Seguridad (acceso privado, URLs temporales).
- Costo y simplicidad de operación.
- No degradar la base de datos transaccional.
- Posibilidad de cambiar de proveedor (puerto).

## Candidatos
- **Supabase Storage** (bucket privado).
- Amazon S3.
- Guardar los archivos en la base de datos (BLOB).
- Disco local del servidor.

## Análisis
| Candidato | Cumple | Razón |
|---|---|---|
| **Supabase Storage** | Sí | Mismo proveedor que la BD, bucket privado, URLs firmadas, plan gratuito. |
| Amazon S3 | Sí | Más robusto, con mayor configuración (IAM); es la evolución natural. |
| BLOB en BD | No | Encarece respaldos y lecturas; mezcla datos y binarios. |
| Disco local | No | El contenedor es efímero (Factor VI); se perderían los archivos. |

## Recomendación
**Supabase Storage** tras el puerto `FileStoragePort`. Metadato (`nombre`, `tipo`, `tamaño`, `sha256`, `clave`) en PostgreSQL. Cuatro estrategias (almacenamiento, seguridad, recuperación y trazabilidad) detalladas en 07 §1.

## Consecuencias
- Descarga solo mediante **URL firmada de vida corta**, emitida tras comprobar el permiso de lectura.
- Validación de tipo (lista blanca y contenido real) y de tamaño antes de almacenar.
- Cada carga y descarga se **audita**.
- Cambiar a S3 implica un nuevo adaptador.
